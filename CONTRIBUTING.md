# Contributing

1. Abre un issue para cambios de contrato o nuevos adapters.
2. Mantén cada adapter aislado y declara sus permisos.
3. No incluyas tokens, claves privadas ni fixtures con secretos.
4. Ejecuta `npm test`, `npm run probe` y `git diff --check` antes de abrir un PR.
5. Las operaciones mutantes deben exigir confirmación explícita.
