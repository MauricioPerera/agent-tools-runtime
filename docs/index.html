The problem

Every tool, every time — whether you need it or not

The usual way to connect an agent to a service is to hand it the full manual before every question.

Wired permanently

Every tool's full instructions, loaded into every conversation, used or not.

Connected on demand

A short menu first. Full instructions arrive only for what actually gets used.

How it works

Ask first. Load exactly what answers.

Every plugin exposes the same three jacks, no matter what it connects to underneath.

  1. 01

    Say what you need

    The agent asks a small, cheap question.

  2. 02

    Get a short list back

    The runtime answers with the handful of things that matter.

  3. 03

    Pick the exact one

    The agent chooses the capability that actually fits.

  4. 04

    Only then, load it

    The full instructions for that one thing arrive.

Every connected service gets the same three doors in.

For builders

Already have an API? You don't need a server to make it agent-ready.

A plugin is a folder the runtime loads directly.

  • Zero infrastructure. Ship a package that wraps the API you already have.
  • Discoverability included. Confirmation on risky calls, error hints, search.
  • Your own shortcuts. Bundle a multi-step recipe into one reliable call.

Quick start

Running in one command

Install the runtime, point it at a plugin, and your agent has a new, small menu to ask from.

mcp-server.mjs
# stdio (default) -- for Claude Code, Claude Desktop, pool, ollama...
npm install @rckflr/agent-tools-runtime
npm run mcp

# Streamable HTTP -- for clients that only speak HTTP/SSE, e.g. eve
npm run mcp:http
